# Hermes 系统能力总览

## 定位

Hermes 是一套老板单人使用场景下的交易决策系统。

它不是通用量化平台，不是金融终端，也不是面向大众用户的产品。

它的设计目标非常集中：

- 输出结构化买卖信号
- 用回测证明哪些信号值得跟
- 给出明确的交易执行计划
- 在后台持续运行并推送关键告警

## 这套系统已经能做什么

### 1. 结构化信号生成

Hermes 不再只输出 `S/A/B/C` 评级。

每个可执行信号都会绑定：

- `rating`
- `confidence`
- `entry_price`
- `stop_loss`
- `take_profit`
- `holding_horizon`
- `signal_valid_until`
- `priority_score`

同时，系统会把信号、生成时价格快照、后续修订历史落库，形成完整的信号记录链路。

### 2. 回测与 edge 量化

Hermes 已完成最小回测闭环：

- 使用 Yahoo Finance 历史价格
- 计算 `5 / 20 / 60` 日 outcome
- 处理价格缺口
- 汇总胜率、平均收益、中位收益、最大回撤、盈亏比
- 按 `grade` 分桶输出 edge 统计

这意味着系统可以明确回答：

- `S` 级历史表现是否显著优于 `A`
- 哪个持有周期更有效
- 某类信号是否真的值得跟

### 3. 交易计划与执行支持

Hermes 现在不止“会分析”，而且“会给计划”。

交易计划层会基于信号生成：

- 是否执行
- 入场区间
- 止损位
- 止盈位
- 建议仓位
- 信号失效条件

系统还支持：

- 持仓记录
- 持仓状态查询
- 模拟交易记录
- 基于持仓上下文的决策告警

### 4. 数据质量与信号排序

Hermes 已有独立的数据质量层，而不是直接把外部数据喂给策略。

现有能力包括：

- Provider 抽象层
- Yahoo Finance provider
- AkShare provider
- 字段校验
- 缺失值处理
- 新鲜度检测
- fallback provider

在信号层，系统还会综合：

- 行业暴露重叠
- 同时出现多个强信号时的排序
- 不同数据源之间的证据冲突
- 不同分析师的动态权重

这些因素已经开始影响最终的 `confidence` 和 `priority_score`。

### 5. 估值、风控与压力测试

Hermes 已经具备一套基础但成体系的估值与风控能力：

- `DCF`
- `DDM`
- 相对估值
- `Sharpe Ratio`
- `Max Drawdown`
- `VaR`

此外，系统已经定义并接入极端市场压力测试：

- `2008_crisis`
- `2020_covid_crash`
- `2022_rate_hike_bear`

压力测试结果会下调信号置信度与优先级，并形成 warning，而不是只做离线分析。

### 6. macOS 服务模式

Hermes 可以作为老板侧长期运行的后台服务。

当前已具备：

- `launchd plist` 自动生成
- `launchctl` 命令封装
- 健康检查
- 心跳与恢复逻辑
- 收盘后 idle 轮询
- 数据异常时降级模式

目标是让 Hermes 在最少人工干预的前提下，持续可用。

### 7. 极简查看器

Hermes 已有最小 Web Viewer，用来查看：

- 当前信号
- 信号优先级
- 开放持仓
- 模拟仓
- 未读告警
- 收盘后简版摘要

这不是完整产品 UI，而是一个足够老板单人使用的轻入口。

## 一次完整链路如何工作

1. 多分析师围绕标的产出研究结论  
2. `GradingAgent` 生成结构化信号  
3. 信号与价格快照进入数据库  
4. 回测管线持续为信号计算 outcome  
5. 交易计划层给出明确执行方案  
6. Monitor 与 Viewer 负责把信号转成实际可见告警与查看结果  
7. macOS 服务模式负责长期运行与恢复

## 适合什么场景

Hermes 当前最适合：

- 单人决策
- 高集中度跟踪少量优先信号
- 需要把研究结论变成可执行动作
- 重视胜率、盈亏比和 ROI 的老板场景

它不适合：

- 多用户平台
- 高频实时撮合
- 券商下单系统
- 通用投资社区产品

## 当前边界

Hermes 的当前版本已经是一套完整骨架，但仍有边界：

- Yahoo Finance 更适合研究与回测，不适合作为高精度实时交易行情源的最终方案
- 极简 Viewer 足够看信号，但不是复杂终端
- 回测能够证明历史 edge，不代表未来收益保证
- 压力测试能提供风险提示，但不能消除市场突发风险

## 核心判断标准

这套系统是否成功，不看页面多少，也不看 agent 数量多少，而看 4 件事：

- 信号是否足够清晰
- 胜率与盈亏比是否有统计优势
- 多信号排序是否合理
- 老板是否愿意把它当成主要信号源

这就是 Hermes 当前版本的工作定义。
